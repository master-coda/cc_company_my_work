# crypto-paper-trading-bot: 売買ロジック検証設計

- 作成日: 2026-09-10
- ステータス: 承認済み（バックテストフェーズの設計）
- 元になった資料: `gemini-code-1788966599058.yaml`（Geminiが生成した初期プラン）

## 背景・経緯

Geminiが生成した初期プラン（`crypto_paper_trading_bot`）は、月利20%（勝率60%・リスクリワード比4:1）を前提に、1〜5分足でのペーパートレードをいきなり実装する内容だった。レビューの結果、以下の問題が見つかった。

1. 「勝率60%」と「RR比4:1」の同時達成は一般に両立しにくい組み合わせであり、根拠となる売買ロジックの検証（バックテスト）がないまま目標値から逆算されていた。
2. 1〜5分足は個人運用のMac miniには不向き（ノイズ過多、手数料負け、API遅延の影響が大きい）。
3. エントリー・エグジットロジックが「ボラティリティを活用した」という抽象的な記述のみで未定義だった。

この設計は、上記を踏まえて「まず売買ロジックをバックテストで検証し、有効性が確認できたものだけをペーパートレードに進める」という順序に組み替えたものである。ペーパートレード自体（実装・運用）は別フェーズとして後日設計する。

## 目的・スコープ

**目的**: トレンドフォロー型・平均回帰型の2つの売買ロジックを、過去データで客観的に比較検証し、どちらが（あるいは両方が）ペーパートレードに進む価値があるかを判断する。

**スコープ外**（今回の設計に含まない）:
- リアルタイムのペーパートレード実装（口座シミュレーター、常時稼働、launchd設定等）
- 実口座API連携（フェーズ3）
- BTC/JPYでの最終検証（本設計はBTC/USDTでのロジック有効性検証に限定）

## 前提・時間軸

- 対象時間軸: 1時間足をメイン（4時間足は補助的な比較対象）
- 対象データ: Binance（ccxt経由）の BTC/USDT、直近2年分
- 通貨ペアの注記: Binanceは BTC/JPY を提供していないため、本検証は BTC/USDT で行う。ロジックの有効性（トレンド/レンジのどちらで勝負できるか）を確認することが目的であり、円建てかドル建てかは検証の本質に影響しないと判断した。本番相当（BTC/JPY）での最終検証は、ロジックが決まった後の別フェーズで行う。

## 検証する2つのロジック

### 戦略A: トレンドフォロー型（ブレイクアウト）

- エントリー条件: ADX(14) > 20（トレンド相場と判定）かつ、終値が直近20期間高値（ドンチャンチャネル）を上抜け → ロング。直近20期間安値を下抜け → ショート。
- 利確: 固定利確なし（トレーリングストップで伸ばす）
- 損切り・エグジット: ATR(14)×2 のトレーリングストップ

### 戦略B: 平均回帰型（レンジ逆張り）

- エントリー条件: ADX(14) < 20（レンジ相場と判定）かつ、終値がボリンジャーバンド(20,2)下限にタッチ／割れ、かつRSI(14) < 30 → ロング。上限＋RSI(14) > 70 → ショート。
- 利確: 移動平均線(20)への回帰、または固定RR比1:1.5のいずれか
- 損切り: 直近スイング高安値、またはATR(14)×1.5

両戦略とも ADX(14)=20 を境にレンジ／トレンドを棲み分けており、比較がフェアになるよう設計している。

パラメータ（ADX閾値、RSI30/70、ATR倍率など）は初期値であり、学習期間でのグリッドサーチにより調整することを前提とする。

## アーキテクチャ

新規プロジェクト `crypto-paper-trading-bot/` を作成し、既存の `freee-accounting-automation/` と同様の `src/` + `tests/` 構成に揃える。

```
crypto-paper-trading-bot/
├── src/
│   ├── data_fetcher.py      # Binance(ccxt)からOHLCV取得・ローカルCSVキャッシュ
│   ├── indicators.py        # ADX, RSI, ボリンジャーバンド, ATR, ドンチャンチャネル, SMA
│   ├── strategies/
│   │   ├── trend_following.py   # 戦略A
│   │   └── mean_reversion.py    # 戦略B
│   ├── backtest_engine.py   # 1本ずつシミュレーション、手数料・スリッページ反映
│   └── evaluator.py         # 勝率/RR比/プロフィットファクター/最大DD/期待値を算出、レポート出力
├── data/                    # 取得したOHLCVキャッシュ（.gitignore対象）
├── tests/
└── requirements.txt
```

## データフロー

1. Binance APIから BTC/USDT の1時間足を2年分取得し、ローカルCSVにキャッシュする（再実行時にAPIを叩き直さないため）。
2. 指標（ADX, RSI, ボリンジャーバンド, ATR, ドンチャンチャネル, SMA）を計算する。
3. 戦略A・Bがそれぞれ独立にシグナルを生成する（共通インターフェース: OHLCV+指標 → エントリー/エグジット）。
4. データを学習期間（直近2年のうち前半約1.5年）と検証期間（後半約0.5年）に分割する。
5. 学習期間でパラメータ調整（ADX閾値、RSI30/70、ATR倍率などのグリッドサーチ）を行う。
6. バックテストエンジンが手数料（Binance想定 0.1%程度）とスリッページを加味してシミュレーションする。初期資金5万円相当・1トレードあたりリスク0.5%のポジションサイジングを適用する。
7. 検証期間で学習済みパラメータの性能を確認し、過学習していないかを判断する。
8. 評価レポート（勝率・RR比・プロフィットファクター・最大DD・期待値・総取引数）をA/B比較形式で、学習期間・検証期間それぞれについて出力する。

## エラーハンドリング

- API取得時のレート制限・タイムアウトはリトライする（指数バックオフ）。
- 欠損足はフラグを立てて除外する（補完すると指標計算が歪むため補完はしない）。
- 損失トレードが0件の場合のRR比計算など、ゼロ除算が起きうる箇所はガードする。

## テスト方針

- 指標計算: `ta`ライブラリの出力と突き合わせて正しさを検証する。
- シグナル生成: 合成OHLCVデータを用いて、狙った条件で狙った通りにエントリー/エグジットするかを単体テストする。
- バックテストエンジン: 手数料控除・ポジションサイジング・損益計算が既知の入力に対して正しい結果を返すかを検証する。

## 技術選定

- 言語: Python 3.x
- ライブラリ: ccxt（データ取得）、pandas（データ加工）、ta または pandas-ta（指標計算）
- バックテストエンジン: `vectorbt` 等の重量級ライブラリではなく、pandasベースの自作エンジンを採用する。データ量（2年分・約1.7万本）とロジックの単純さを踏まえ、パフォーマンスより透明性・改造しやすさを優先する。

## 次のステップ（本設計のスコープ外）

- バックテスト結果を踏まえ、どちらの戦略（あるいは両方）をペーパートレードに進めるか判断する。この判断はObsidian Vault（`CCtoObsidian/Decisions/`）に意思決定ログとして記録する。
- ペーパートレード実装（仮想口座シミュレーター、常時稼働、launchd設定等）は別設計として、この検証結果が出てから着手する。
